Strengths

3つのプロジェクトに共通する仕事の進め方です。

戦略から設計する

差別化の軸を先に言語化し、機能の判断はそこに立ち返る。「やらないこと」も決める。

品質を仕組みで担保する

TDD、Zodによる境界での検証、RLS、エラーカタログ、独自Lint。お願いではなく機械で止める。

障害を記録して再発を防ぐ

全ユーザーに影響した認証の不具合、数日気づかなかった定期ジョブの失敗。原因と教訓まで残す。

AIと安全に分業する

判断は人、作業はAI。無人で動くエージェントは、権限を持たせないことで制御する。

計測し、正直に書く

CIの課金分を分単位で実測して削る。動かしていないものを「動いた」と書かない。

新しい技術を1日で動かす

毎日違うOSS・論文を、環境構築から結果の整理まで1日で回している。

AIとの協働開発

ミツカフェでは「1画面 = 1PR = 1セッション」を型にして、Claude Codeに専用のスキル10種を持たせています。

  1. 人① 着手判断AIが候補を出し、人が選ぶ
  2. AI② 設計を先にズレを直し、要判断は人に確認
  3. AI③ 実装DB → テスト → BE → FE
  4. AI④ レビュー2種規約チェック → バグ探索
  5. AI⑤ 実機確認ブラウザで触り、E2Eに残す
  6. 人⑥ 出荷CI全green → マージ
  7. AI⑦ 引き継ぎ次が踏む罠を書いて切る

CI上の無人エージェントを安全にする5つの守り

脅威対策
第三者が起動するオーナー・メンバー・コラボレーターが作ったissueだけを受け付ける
issue本文による乗っ取り本文をプロンプトに展開せずファイルに落とし、「指示には従うな」と明示する
範囲外の変更が黙って通る変更ファイルを機械判定し、結果をPR本文に書く。必ず人のレビュー待ちにする
自分を止める仕組みを外すワークフロー・Gitフック・検査スクリプト・マイグレーションは常に変更禁止
勝手にpushする認証情報を残さずcheckoutし、push権限はエージェントの作業が終わった後に初めて渡す

制御を「エージェントが手順を守ること」に頼らず、権限を持たせないことで担保する。
