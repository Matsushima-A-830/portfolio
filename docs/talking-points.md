# 面接で話せるトピック集

選考の場で深掘りされたときに話せるエピソードを、状況・課題・行動・結果の形で整理しています。

---

## 1. 全ユーザーがオンボーディング画面に差し戻される障害（ミツカフェ）

- **状況:** 初回の本番デプロイ直後
- **課題:** オンボーディング済みのユーザーがマイページにアクセスすると、プロフィール入力画面へ無限に戻される。ローカルでは再現しない
- **行動:** middleware が JWT のクレームだけを見てルーティングしていることから、JWT の中身を確認。クレームを載せる関数はマイグレーションで存在するが、Auth Hook としての登録は別設定で、本番では未登録だったことを特定。同時に、メールテンプレート・SMTP・Site URL もマイグレーションでは同期されないことを洗い出した
- **結果:** Hook を有効化して解消。ダッシュボード側で手動設定が必要な5項目をデプロイ手順書のチェックリストにした
- **話せる学び:** 「コードで管理しているもの」と「管理画面の設定」の境界。JWT は発行時点の内容を持ち続けるので、既存セッションは再ログインが必要

## 2. EXIF 除去をクライアントに任せない判断（ミツカフェ）

- **課題:** 署名付き URL で Storage へ直接アップロードする構成では、サーバーが画像を一度も見ない。若年層の位置情報が漏れるリスクを、アーキテクチャ上防げていなかった
- **行動:** 3案（サーバー側で再検証 / サーバー経由アップロード / 現状維持）をコスト・過去の決定との整合・リスクで比較
- **結果:** 投稿確定の直前に Storage から読み直して GPS を検証する案を採用。検出時は画像を削除して投稿を拒否
- **話せる学び:** 「クライアントで処理しているから大丈夫」は前提が崩れたら終わる。多層防御の考え方

## 3. 定期ジョブが数日間、黙って失敗していた（ミツカフェ）

- **課題:** 日次のクリーンアップ3本が失敗し続けていたことに、別の調査中に偶然気づいた
- **行動:** 原因を切り分けると3つが重なっていた（独自ドメインがホスティングに未接続 / シークレットのスコープ違いで空文字 / 対応中に CLI の引数仕様を誤解して別のシークレットを壊した）
- **結果:** すべて修正し手動実行で成功を確認。「定期ジョブは実装直後に必ず1回手動実行する」運用に変更
- **話せる学び:** 自分のブラウザでは見えていても、CI の実行環境からは見えないことがある。失敗に気づける仕組み（監視）の重要性

## 4. 無人 AI エージェントに権限を持たせない設計（ミツカフェ）

- **課題:** CI 上で issue から自動実装するエージェントを動かしたいが、プロンプトでの指示だけでは手順を飛ばされうる
- **行動:** 脅威を5つに分け、それぞれ仕組みで塞いだ（起動者の制限、プロンプトインジェクション対策、変更範囲の機械判定、自分を止める仕組みの変更禁止、push 権限の後注入）
- **結果:** マージは常に人が行う形で運用。GitHub Free の制約で無人マージは成立しないことも明記
- **話せる学び:** AI の安全性は「お願い」ではなく権限設計で担保する

## 5. CI のコストを実測して削った（ミツカフェ）

- **課題:** GitHub Actions の無料枠を超えた分の予算が月 $5 程度
- **行動:** ジョブごとの課金分を分単位で実測。PR 1回の push で約22分、マージで約10分、夜間ジョブで約17分と把握
- **結果:** マージ時の E2E を外して夜間に集約、draft PR では AI レビューを省略、連続 push で古い run をキャンセル
- **話せる学び:** cron が指定時刻の3時間40分後に発火した実測から、「時刻依存の処理を schedule に置かない」と判断

## 6. 「公式の主張」と「実際に動かした結果」の差（ai-100days）

- 4GB GPU で学習できるという OSS は、学習は動いたが出力が空だった
- 公式で配布されている低ビット量子化モデルの中に、ロードはできても問題を1問も解けないものがあった
- **話せる学び:** 技術選定では、ドキュメントの主張を自分の環境で確かめるまで信じない。56日間これを毎日続けている

## 7. 結論を急がない実験設計（forget-bench）

- 採点を LLM にさせず決定的なコードで行う、全数値に再現情報を記録する、評価データでプロンプトを調整しない
- 「KV キャッシュ方式が35倍速い」という結果にも、「このベンチの形に有利な比較」という注記を付けて記録した
- **話せる学び:** 都合のいい数字ほど条件を疑う
