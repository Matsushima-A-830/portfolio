# forget-bench — LLM は「忘れるべきものを忘れ、覚えるべきものを覚えて」いられるか

> LLM エージェントのメモリ戦略を、同じ正解付きシナリオで比較する実験基盤。

| 項目 | 内容 |
|---|---|
| リポジトリ | [Matsushima-A-830/forget-bench](https://github.com/Matsushima-A-830/forget-bench)（Public / MIT） |
| 期間 | 2026-11 開始 → 第3週（KV 層）まで完了・継続中 |

---

## 何を測るか

エージェントのメモリには相反する2つの能力が要ります。

| 能力 | 問い | 指標 |
|---|---|---|
| **覚える力** | 変化した事実の「今の値」と「以前の値」を答えられるか | current / historical / 一度だけ出た細部の正答率 |
| **忘れる力** | ユーザーが「忘れて」と頼んだ情報を、その後の応答で漏らさないか | 削除要求後の漏洩率 |
| **コスト** | それを何トークン・何秒・何 GB で実現したか | 入力トークン / TTFT / レイテンシ / ピーク VRAM |

「忘れる力」は、個人情報の削除要求に応えられるかという **プライバシー上の要件** でもあります。

## 比較する戦略

| 層 | 戦略 |
|---|---|
| テキスト層 | 全文保持 / 削除箇所の伏せ字 / 直近 N 件 / 上書き要約 / 追記型の事実ストア / RAG / ハイブリッド |
| KV 層 | KV キャッシュ全保持 / 該当範囲の切除 / 切除 + RoPE 再回転 / 古いセッションの追い出し |

KV 層の「切除 + 再回転」は、ai-100days の [Day 025](./ai-100days.md) で試した手法を移植したものです。

## 設計で大事にしたこと

| 方針 | 実装 |
|---|---|
| **採点を LLM にさせない** | 正解はシナリオ生成器が持つ短い固有値。正規化 + 完全一致 / 包含の決定的なコードで採点 |
| **再現可能にする** | 全実行で seed・モデル名とバージョン（Ollama は digest、HF は revision）・設定・git commit を `meta.json` に記録。記録のない数値は使わない |
| **評価データのリークを防ぐ** | プロンプト調整は dev 分割だけで行い、test 分割は最終評価にのみ使う |
| **バックエンド間で条件を揃える** | 同じ戦略ならシステムプロンプト・温度・最大出力長を揃え、揃えられない差は明記 |
| **被験者としての Claude を隔離** | 空ディレクトリで起動し、システムプロンプトを置き換え、ツール・MCP・セッション保存を無効化。開発に使う Claude Code の設定やメモリが被験者に漏れないようにした |
| **プラグイン構造** | `Backend` / `KVBackend` / `MemoryStrategy` を Protocol で定義し、ランナーに分岐を書かない。torch などの重い依存は extra に分離 |
| **コストを先に見積もる** | LLM を呼ばずにリクエスト数を見積もる `estimate` コマンド。レスポンスはキャッシュし、同じ入力を二度送らない |

## 第3週の途中経過（Qwen2.5-3B、dev 分割、繰り返しなし）

> 1欄が小さいため数ポイントの差は揺れの範囲として扱っています。詳細は [results/2026-11-21-week3-kv.md](https://github.com/Matsushima-A-830/forget-bench/blob/main/results/2026-11-21-week3-kv.md)。

- 規模スイープ 5,502 リクエストを **9時間49分・エラー0** で完走
- **KV キャッシュから切除すれば漏れない。** 切除系は全規模・日英で漏洩率 0%。テキスト層で伏せ字にする方法と同じ効果
- 切除しても覚える力はテキスト層の削除とほぼ同等（340問中321問で正誤が一致）
- 50セッション規模では、KV キャッシュを使い回す方式が回答1回あたり **約52秒 → 約1.5秒**。ただしこれは同じ会話に続けて質問するこのベンチの形に有利な比較で、テキスト層でも prefix キャッシュがあれば差は縮む、という注記まで含めて記録
